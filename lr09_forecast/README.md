## 2. Як рахувалася симуляція

| Поле | Значення |
| --- | --- |
| Інструмент | Власний скрипт Python (`lr09_forecast/monte_carlo.py`, модуль `random`, `seed = 42`) |
| Прогонів | 10000 |
| Що тягнеться випадково | `points_done` одного з моїх спринтів із `velocity.csv` (`11` або `19` points із поверненням) |
| Як рахується дата прогнозу | Останній день спринта, на якому закінчується робота: для сценарію «Весь перший реліз» кінець спринта 1 (`2026-10-02`) плюс `(P − 1) × 14` днів, для сценарію залишку кінець останнього спринта (`2026-10-16`) плюс `P × 14` днів |

Код симуляції лежить поруч у `lr09_forecast/monte_carlo.py`:

```python
import random
from collections import Counter

def simulate_sprints(velocities, remaining_points, n_sims=10000, seed=42):
    rng = random.Random(seed)
    outcomes = []
    for _ in range(n_sims):
        rem = remaining_points
        sprints = 0
        while rem > 0:
            rem -= rng.choice(velocities)
            sprints += 1
        outcomes.append(sprints)
    outcomes.sort()
    p50 = outcomes[int(0.50 * n_sims) - 1]
    p85 = outcomes[int(0.85 * n_sims) - 1]
    p95 = outcomes[int(0.95 * n_sims) - 1]
    return p50, p85, p95, Counter(outcomes)
```

Якщо порахувати залишок у 60 points (90 мінус 30 закритих за два спринти) одною цифрою та вилкою без симуляції: за середнім темпом `60 / 15 = 4` спринти, за найкращим `60 / 19 = 3.16` → 4 спринти, за найгіршим `60 / 11 = 5.45` → 6 спринтів. Симуляція на 10 000 прогонів для залишку 60 points дала такий розподіл: 4 спринти — 6919 прогонів (69.2%, це P50), 5 спринтів — 2753 прогони (разом 96.7%, це P85 і P95), 6 спринтів — 328 прогонів (100%).
